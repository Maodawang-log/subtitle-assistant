# ADR-0024：学习控件等待 B 站页面接管后再挂载
> 状态：有效（2.6.3.6 页面兼容修复）；为 ADR-0023 的文档流挂载增加前置条件

用户在同一 Edge 内关闭插件并刷新后，右上导航、推荐缩略图和评论均恢复。本轮只处理该页面兼容问题，保留既有词典异写合并；模型管理、标题调整、字幕拖选及其他讨论中的功能继续暂停。

## 因果证据

在隔离 Edge 的同一公开 B 站视频上进行组件对照，学习始终未开启：

| 变体 | 消息/动态/收藏/历史 | 已载入推荐图 | 评论组件及评论行 | 页面异常 |
| --- | --- | ---: | --- | --- |
| 2.6.3.5 全部脚本 | 缺失 | 0 | 未生成 | HierarchyRequestError |
| 无内容脚本的对照扩展 | 正常 | 22 | 已生成 | 无 |
| 仅 MAIN 播放器观察脚本 | 正常 | 22 | 已生成 | 无 |
| 仅学习界面内容脚本 | 缺失 | 0 | 未生成 | HierarchyRequestError |
| 保留全部脚本，仅暂停未开启时的 DOM 挂载 | 正常 | 22 | 已生成 | 无 |

原版首次将控件插入 `#app` 时，该根仍带 `data-server-rendered="true"`。随后 B 站 Vue 生产代码在 `$mount` / hydration 路径的 `appendChild` 抛出节点类型异常，页面初始化中断。移除挂载这一单一因素就恢复，证据不支持将本问题归因于播放器观察器、用户登录或网络。

[Vue 2 官方 hydration 说明](https://v2.ssr.vuejs.org/guide/hydration.html) 说明该属性标记服务端 DOM，客户端接管要求结构匹配；生产模式省略了开发模式的结构断言。隐藏控件也会改变节点顺序，CSS 修饰不能修复初始化失败。

## 决定

`createStudyShell().mount()` 在视频尚未连接，或 `#app` 仍带 `data-server-rendered` 时直接返回。插件宿主保留在站点应用根之外，既有 250ms 同步周期等待 Vue 消费该标记后再挂载。没有新增轮询、固定延时、全局原型补丁或页面脚本拦截；播放器观察逻辑原样保留。

门槛对学习关闭及过早手动开启均成立；通过后仍采用原有外层播放器后的占位和右栏阅读区。若站点自身尚未完成接管，插件入口稍后显示，而不会为了显示入口抢先改动其服务端 DOM。

## 回归与限制

修后同一匿名页面的导航、22 张有实际自然尺寸的推荐图、`bili-comments` 和其评论行恢复，未再出现 hydration 异常。禁用缓存并将真实页面主脚本延迟 6 秒后，SSR 标记仍在约 6.1 秒的采样期间保留；控件在标记消失后才进入应用根，页面正常完成初始化。

另以真实评论行、图片自然尺寸和学习按钮状态断言冷开、开启、关闭恢复、刷新及跳转到第二个公开视频；保留窄屏、全屏和原生试看提示避让检查。没有在用户原浏览器安装或覆盖原加载目录，没有调用付费接口或修改本地识别服务。

用户提供的另一个视频 URL 在匿名隔离环境跳转到首页，因此不能把该 URL 的用户登录环境修复状态列作已实测；可用公开视频上的因果复现与修后回归独立成立。未来若 B 站更换 SSR 框架或标记，应重新验证本门槛，不能假设它适用于任意站点。
